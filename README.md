# BMore Cardiology

Static patient education website at [bmorecardiology.com](https://bmorecardiology.com/), maintained by Dr. Jeremy Pollock. GitHub Pages serves the committed HTML, CSS, JavaScript and PDFs; deployment does not require a build service.

## Edit and preview

Education copy and reference URLs are in `scripts/content_data.py`. Shared navigation, page layout, home page and indexes are generated by `scripts/build_site.py`. The About biography is preserved between its `BIOGRAPHY` markers. Tracker markup is in `app/tracker-fragment.html`, behavior in `app/tracker.js` and measurement handling in `app/tracker-core.js`.

After editing, regenerate the HTML and preview from the repository root:

```sh
python3 scripts/build_site.py
python3 -m http.server 8000
```

Open `http://localhost:8000/` and use the existing site password. Keep the generated HTML in the same commit as its source changes. Update `UPDATED` in the content data when publishing a substantive content revision. Add actual reviewer fields only after medical review.

## Printable handouts

The five test summaries and BP log are generated by `scripts/build_handouts.py` into `downloads/`. Install ReportLab in a development environment, then run:

```sh
python3 -m venv .venv
.venv/bin/pip install reportlab
.venv/bin/python scripts/build_handouts.py
```

Review each regenerated PDF visually and confirm it remains one page. Commit the PDFs together with the source change.

## Validate and review

```sh
python3 scripts/check_site.py
node --test qa/tracker.test.cjs
```

Browser setup, automated checks and the real-device checklist are in [docs/browser-review.md](docs/browser-review.md). Medical review details are in [docs/clinical-review.md](docs/clinical-review.md). Proposed recording scripts are in [docs/video-scripts.md](docs/video-scripts.md).

The browser test uses fictional data in a fresh browser context on localhost. The tracker retains the original `vitalReadings` localStorage key and does not transmit measurements. It uses the same origin and browser profile to access prior readings; previews on another origin have separate storage.

Create a review branch and PR for changes. After clinical and browser review, merge through the agreed GitHub workflow and verify the GitHub Pages deployment.
